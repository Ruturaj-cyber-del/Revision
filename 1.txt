2. DOCKER COMPOSE — MULTIPLE HTTPD CONTAINERS

## Aim

To create and run two Apache HTTPD containers using Docker Compose, host separate websites on different ports, and link the webpages.

## Requirements

- Debian 13 VM or AWS Debian instance
- Docker Engine installed
- Docker Compose plugin
- Internet connectivity
- Add the 8081 and 8082 in aws instance traffic
- add the current user into the docker group

---

## Step 1: Verify Docker Compose

```
sudo docker compose version
```

If unavailable, install the Compose plugin if provided by your configured Debian repository:

```
sudo apt update
sudo apt install docker-compose -y
```

Verify the available command:

```
docker-compose version
```

Use `docker compose` if the plugin is installed; otherwise use `docker-compose` where supported.

---

## Step 2: Create Project Directories

```
mkdir docker-compose-practical
cd docker-compose-practical

mkdir site1 site2
```

Directory structure:

```
docker-compose-practical/
├── compose.yaml
├── site1/
│   └── index.html
└── site2/
    └── index.html
```

---

## Step 3: Create Website 1

```
nano site1/index.html
```

Add: To access from the browser add the aws pubilic ip insted of localhost in both index file 

```
<html>
<body>
<h1>Welcome to Website 1</h1>
<a href="http://localhost:8082">Visit Website 2</a>
</body>
</html>
```

Save and exit.

---


## Step 4: Create Website 2

```
nano site2/index.html
```

Add:

```
<html>
<body>
<h1>Welcome to Website 2</h1>
<a href="http://localhost:8081">Visit Website 1</a>
</body>
</html>
```

Save and exit.

---

## Step 5: Create Docker Compose File

```
nano compose.yaml
```

Add:

```
services:
  web1:
    image: httpd:latest
    container_name: compose-web1
    ports:
      - "8081:80"
    volumes:
      - ./site1:/usr/local/apache2/htdocs:ro

  web2:
    image: httpd:latest
    container_name: compose-web2
    ports:
      - "8082:80"
    volumes:
      - ./site2:/usr/local/apache2/htdocs:ro
```

Save and exit.


---

## Step 6: Validate Compose Configuration

```
sudo docker compose config
```

This checks the Compose YAML configuration.

## Step 7: Start Both Containers

```
sudo docker compose up -d
```

- `up`: Creates and starts services.
- `-d`: Runs containers in the background.

## Step 8: Verify Containers

```
sudo docker compose ps
```

Expected containers:

- `compose-web1`
- `compose-web2`

## Step 9: Test Both Websites

Test Website 1:

```
curl http://localhost:8081
```

Test Website 2:

```
curl http://localhost:8082
```

Expected output should contain:

```
<h1>Welcome to Website 1</h1>
```

and:

```
<h1>Welcome to Website 2</h1>
```

Open in browser:

```
http://VM-IP-ADDRESS:8081
http://VM-IP-ADDRESS:8082
```

Click the links to navigate between the websites.

**Note:** For AWS or remote VM access, allow only the required inbound TCP ports from the required source IP/network.

---

## Step 10: Useful Docker Compose Commands

```
# List services
sudo docker compose ps

# View logs
sudo docker compose logs

# Follow logs
sudo docker compose logs -f

# Stop containers
sudo docker compose stop

# Start stopped containers
sudo docker compose start

# Restart services
sudo docker compose restart

# Stop and remove containers and network
sudo docker compose down
```
## Cleanup

```
sudo docker compose down
```

This removes the containers and default Compose network. Website files remain in the project directory.

3. DOCKER SWARM — CLUSTER AND SERVICE DEPLOYMENT

## Aim

To initialize a Docker Swarm cluster, join worker nodes, deploy a replicated HTTPD service, and scale the service.

## Requirements

- Minimum 2 Debian 13 VMs or AWS EC2 instances.
- Docker installed on both machines.
- Network connectivity between nodes.
- SSH access to both machines.

## Node Configuration

| Machine | Role |
|---|---|
| VM1 | Swarm Manager |
| VM2 | Swarm Worker |

Use private IP addresses for communication between nodes.

---

## Step 1: Verify Docker on Both Machines

Run on VM1 and VM2:

```bash
sudo docker --version
sudo systemctl status docker
```

## Step 2: Initialize Swarm on Manager

Run on VM1:

```bash
sudo docker swarm init --advertise-addr MANAGER_PUBLIC_IP
```

Example:

```bash
sudo docker swarm init --advertise-addr 172.20.5.10
```

Expected result: Swarm initialized successfully and VM1 becomes the manager.

## Step 3: Generate Worker Join Command

On VM1:

```bash
sudo docker swarm join-token worker
```

Copy the displayed join command.

Example:

```bash
sudo docker swarm join --token SWMTKN-1-xxxx MANAGER_PRIVATE_IP:2377
```

## Step 4: Join Worker Node

On VM2, execute the actual join command obtained from VM1:

```bash
sudo docker swarm join --token WORKER_TOKEN MANAGER_PRIVATE_IP:2377
```

Expected result:

```text
This node joined a swarm as a worker.
```

## Step 5: Verify Cluster Nodes

On VM1:

```bash
sudo docker node ls
```

Expected nodes:

- VM1 — Manager / Leader
- VM2 — Worker / Ready

## Step 6: Deploy HTTPD Service
*** Add the 2377 and 8080 in inbound of instances

On VM1:

```bash
sudo docker service create \
  --name webservice \
  --replicas 3 \
  --publish published=8080,target=80 \
  httpd
```

## Step 7: Verify Service

```bash
sudo docker service ls
```

View individual tasks:

```bash
sudo docker service ps webservice
```

Expected result: Three running replicas, distributed across available nodes when resources and scheduling permit.

## Step 8: Scale the Service

Increase replicas to five:

```bash
sudo docker service scale webservice=5
```

Verify:

```bash
sudo docker service ls
sudo docker service ps webservice
```

Expected result: Five running replicas.

## Step 9: Test the Website

From VM1:

```bash
curl http://localhost:8080
```

Open in browser:

```text
http://MANAGER_PUBLIC_IP:8080
http://NODE_PUBLIC_IP:8080
```

Expected result: Apache HTTPD test page.

---

## Important Docker Swarm Commands

```bash
# Check Swarm status
sudo docker info

# List cluster nodes
sudo docker node ls

# List services
sudo docker service ls

# Inspect service
sudo docker service inspect webservice

# List service tasks
sudo docker service ps webservice

# Scale service
sudo docker service scale webservice=2

# View service logs
sudo docker service logs webservice

# Remove service
sudo docker service rm webservice

# Generate worker join token
sudo docker swarm join-token worker

# Leave Swarm (worker)
sudo docker swarm leave

# Leave Swarm (manager, after removing services/nodes)
sudo docker swarm leave --force
```

## Required Network Ports

Allow these ports only between trusted Swarm nodes:

| Port | Protocol | Purpose |
|---|---|---|
| 2377 | TCP | Cluster management |
| 7946 | TCP/UDP | Node communication |
| 4789 | UDP | Overlay network traffic |
  8080

## Cleanup

On VM1:

```bash
sudo docker service rm webservice
```

On VM2:

```bash
sudo docker swarm leave
```

On VM1:

```bash
sudo docker swarm leave --force
```

4. Jenkins CI/CD with GitHub, Docker and NGINX

## 1. Machine Requirements

Use **one Debian 13 machine** for:
- Jenkins
- Docker
- Git
- NGINX containers

Use your computer's browser and GitHub website for configuration.

## 2. Install Required Packages

**Run on: Debian machine**

```bash
sudo apt update
sudo apt install -y git docker.io
sudo systemctl enable --now docker
```

Verify:

```bash
git --version
sudo docker version
```

## 3. Install Jenkins

**Run on: Debian machine**

Create `jenkins.sh`:

```bash
#!/bin/bash
set -e

sudo apt update
sudo apt install -y fontconfig openjdk-21-jre wget

java -version

sudo mkdir -p /etc/apt/keyrings

sudo wget -O /etc/apt/keyrings/jenkins-keyring.asc \
https://pkg.jenkins.io/debian-stable/jenkins.io-2026.key

echo "deb [signed-by=/etc/apt/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/" \
| sudo tee /etc/apt/sources.list.d/jenkins.list > /dev/null

sudo apt update
sudo apt install -y jenkins

sudo systemctl enable jenkins
sudo systemctl start jenkins
sudo systemctl status jenkins --no-pager

sudo cat /var/lib/jenkins/secrets/initialAdminPassword
```

Execute:

```bash
chmod +x jenkins.sh
./jenkins.sh
```

## 4. Configure Jenkins

**Perform in: Browser**

1. Open `http://SERVER_IP:8080`.
2. Enter the initial administrator password.
3. Select **Install suggested plugins**.
4. Create an administrator account.

## 5. Configure Docker Access

**Run on: Debian machine**

```bash
sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
```

Verify:

```bash
id jenkins
sudo -u jenkins docker version
```

## 6. Generate GitHub SSH Key

**Run on: Debian machine**

```bash
sudo -u jenkins mkdir -p /var/lib/jenkins/.ssh

sudo -u jenkins ssh-keygen -t ed25519 \
-f /var/lib/jenkins/.ssh/github_key \
-C "jenkins-github" -N ""

sudo chmod 600 /var/lib/jenkins/.ssh/github_key
sudo chmod 644 /var/lib/jenkins/.ssh/github_key.pub
```

Display public key:

```bash
sudo cat /var/lib/jenkins/.ssh/github_key.pub
```

## 7. Add Public Key to GitHub

**Perform in: GitHub website**

1. Create a repository named `jenkins-nginx-project`.
2. Open **Settings → Deploy keys**.
3. Click **Add deploy key**.
4. Title: `Jenkins Debian`.
5. Paste the public key.
6. Keep write access disabled.
7. Click **Add key**.

## 8. Add Private Key to Jenkins

**Perform in: Jenkins browser dashboard**

1. Open **Manage Jenkins → Credentials**.
2. Select the appropriate global domain.
3. Click **Add Credentials**.
4. Select **SSH Username with private key**.
5. Configure:

| Field | Value |
|---|---|
| ID | `github-ssh` |
| Username | `git` |
| Private Key | Enter directly |

**Get private key: Run on Debian machine**

```bash
sudo cat /var/lib/jenkins/.ssh/github_key
```

Copy the private key and paste it into Jenkins under **Private Key → Enter directly**. Save.

## 9. Create NGINX Project

**Run on: Debian machine**

```bash
mkdir -p ~/jenkins-nginx-project
cd ~/jenkins-nginx-project
```

Project structure:

```text

├── index.html
├── Dockerfile
└── Jenkinsfile
```

## 12. Create Jenkinsfile

**Run on: Debian machine, inside `~/jenkins-nginx-project`**

```bash
nano Jenkinsfile
```

Enter:

```groovy
pipeline {
    agent any

    stages {

        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Build Docker Image') {
            steps {
                sh 'docker build -t my-nginx-website:pipeline .'
            }
        }

        stage('Remove Old Container') {
            steps {
                sh 'docker rm -f jenkins-nginx-pipeline || true'
            }
        }

        stage('Deploy NGINX') {
            steps {
                sh '''
                    docker run -d \
                    --name jenkins-nginx-pipeline \
                    --restart unless-stopped \
                    -p 8087:80 \
                    my-nginx-website:pipeline
                '''
            }
        }

        stage('Verify Deployment') {
            steps {
                sh 'docker ps'
                sh 'sleep 3 && curl -f http://localhost:8087'
            }
        }
    }
}
```

Save the file.

def lambda_handler(event, context):
